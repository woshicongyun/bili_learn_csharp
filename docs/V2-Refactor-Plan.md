# V2 重构方案（聚焦核心 · 保持扩展）

> 决策日期：2026-08-23
> 定调：不追求全包全揽，聚焦「视频处理 → 分析学习 → 归纳沉淀」这一核心流程，同时保留清晰的可扩展性。一切外围功能（评论区、多源、技能沉淀等）作为**可插拔扩展**，不挤占主线。

---

## 一、核心愿景（一句话）

**把 B 站视频吃透，沉淀成桌宠「记得住、接得上、做得到」的立体知识，并作为通用能力引擎的地基。**

核心流程闭环：
```
视频处理 → 分析学习 → 归纳沉淀（知识库 + 记忆 + 技能）
```

---

## 二、V2 架构（纵切式，方案B）

痛点：V1 改一个功能要跨 入口→编排→服务→处理器 四处跳，AI 维护认知负担大、反复试错烧 token。
解法：按业务能力竖切，每条竖柱自成闭环，改动锁死在柱内。

```
BiliLearn/
├── Entry/                    # 入口层（唯一暴露 XML 函数）
│   ├── BiliLearnModule.cs    # 路由 + 配置声明 + Poke 转发（永远瘦）
│   └── Bootstrapper.cs       # 服务装配（DI）
│
├── Capabilities/             # 纵切核心：一个核心能力一条柱
│   ├── Learn/                # 核心：视频学习（单视频 + 队列）
│   │   ├── ILearnService.cs
│   │   ├── LearnService.cs       # 单视频流程
│   │   ├── LearnQueue.cs         # 队列（预下载并行+分析串行）
│   │   └── LearnModels.cs        # 状态机模型
│   ├── Search/               # 核心：WBI 签名搜索
│   ├── Auth/                 # 核心：扫码登录/Cookie
│   ├── Analyze/              # 核心：分析管线（视觉/ASR/字幕）
│   │   ├── VisionAnalyzer.cs
│   │   ├── AudioAnalyzer.cs
│   │   ├── SubtitleAnalyzer.cs
│   │   └── AnalyzeModels.cs
│   └── (扩展柱)              # 见「扩展性」章节
│
├── Shared/                   # 跨能力共享（稳定）
│   ├── BilibiliApiClient.cs  # HTTP + WBI + Cookie
│   ├── LLMClient.cs
│   ├── FFmpegHelper.cs
│   └── Models/
│
├── Storage/                  # 知识库/归档（后续接 SQLite）
└── Docs/                     # 每能力一本自述文档
```

**核心规则**：
1. 改一个能力只动柱内文件
2. 每条柱 = 接口 + 实现 + 模型 + 自述文档
3. 新增能力 = 新增一条柱，不动现有柱
4. 入口层永远瘦，只做路由

## 三、核心流程（聚焦主线）

### 学习流程（Learn 柱）
```
输入BV号
  ├─ 预下载（并行，并发2）
  ├─ 分析（串行）
  │   ├─ 视频信息（标题/简介/UP主/时长）
  │   ├─ 视觉抽帧（VisionAnalyzer）
  │   ├─ ASR转写（AudioAnalyzer）
  │   └─ 字幕三源互校（player/v2/conclusion，SubtitleAnalyzer）
  ├─ LLM归纳（总结 + 知识点 + 金句）
  └─ 归档（知识库 + 记忆快照）
```

### 队列调度（LearnQueue）
- 预下载并行 + 分析串行，避免抢 GPU
- 状态机 `VideoStatus` 带转移校验，非法转移直接拒绝
- 批量入队（LearnBatch）、取消（单个/全部）、状态查询（QueueStatus）

## 四、迁移策略（渐进式）

原则：V1 能用先跑，新能力在哪、V2 拆到哪。

| 阶段 | 内容 | Token 占比 | 外包 |
|------|------|-----------|------|
| 一 | 搭骨架（Entry+Bootstrapper+Shared） | 8%~12% | ❌ 不外包（框架耦合深） |
| 二 | 拆 Learn 柱（含队列状态机） | 30%~35% | ⚠️ 半外包（给规格，测试亲盯） |
| 三 | 拆 Search/Auth/Analyze | 35%~40% | ✅ 全外包（纯搬移） |
| 四 | 废弃 V1 + Storage 落库（SQLite） | 15%~20% | ⚠️ 半外包（给ER图，盯废弃） |

每阶段独立编译 + 实测通过才进下一阶段。

## 五、扩展性（可插拔，不挤占主线）

目标：核心流程稳定后，外围能力以独立柱子形式平滑接入。

### 近期扩展（基础）
- **视频标签**：`Shared/Models` 补 `Tags` 字段，详情接口取 `tag` 数组归档，可选 LLM 归一。为分类检索打基础。+3%~5% token

### 中期扩展
- **评论区数据源**：新增 `Capabilities/Comments/` 柱，`/x/v2/reply/main` 拉热评 + LLM 提炼观点，作为视频元数据。+8%~10% token
- **多源录入**：喂文档/网页/聊天记录，沉淀进同一套知识摄入管线（架构天然支持）

### 远期扩展（知识库出口）
- **记忆系统打通**（详见第六节）
- **技能沉淀**：步骤式视频提炼成 `SKILL.md` 注册进技能库

**扩展原则**：核心流程（Learn/Search/Auth/Analyze）永远优先，扩展柱逐个接入、验证通过再接下一个，不并行铺开。

## 六、构想九：知识库 ⇄ 记忆系统打通

让知识从「主动去翻的库」变成「自然被想起、被调用的能力」。

### 三层打通
1. **摄入**：学习收尾时写记忆快照（BV号+主题标签+金句+可聊钩子+技能引用）
2. **唤起**：聊天时记忆检索命中 → 主动接话；周期报点翻记忆 → 主动开话题
3. **执行**：技能索引触发 → 调 `SKILL.md` 执行

### 数据流
```
学习完成 → 知识库归档 + 记忆快照 + 技能注册
聊天时   → 话题命中记忆 → 引用知识库详情
技能调用 → 记忆触发 → 调 SKILL 执行
```

### 落地节奏（控制成本）
- **近期**（阶段三/四内）：打通「学习→记忆快照」，让知识开始进记忆
- **远期**（V2 稳定后）：主动唤起 + 跨视频技能合并

---

## 七、价值判断与合作原则

### 价值
1. **桌宠质变**：从「会说话的玩具」到「有内涵、会成长的伙伴」
2. **通用引擎**：这套「摄入→记忆→技能→输出」是 Alife 桌宠生态的能力地基，不限 B 站
3. **「我记得」**：最动人的是主人随口聊起，我能接「说到这个，我之前学过……」

### 合作原则（主人 + 真央共同守）
1. **聚焦**：不追求全包全揽，死磕核心流程（视频→分析→归纳）
2. **质量优先**：价值不在功能多全，在「记得准、接得住、做得到」
3. **控成本**：小步快跑，先验证「我记住了」再铺开，盯紧 token
4. **不贪多**：扩展柱逐个接入，验证通过再接下一个
